# 11. 学习复盘闭环

ChainMind 不应该长期停留在固定规则系统。项目需要通过推送后的真实表现、用户反馈和历史样本回测，不断校正评分规则和推送策略。

## 核心分工

```text
ChainMind 实时评分：负责当下判断
Hermes / learning 层：负责复盘学习
规则版本：负责把学习结果沉淀为可追踪的调整
```

Hermes 可以学习，但重点不是直接替代评分系统，而是做复盘、归因和策略建议。

## 学习什么

学习层主要分析：

- A/B/C/D 分级是否过松或过严。
- 哪些指标经常导致误报。
- 哪些 D 级 token 后来表现很好，说明可能漏报。
- 哪些钱包信号真的可复制。
- 哪些重点钱包最近失效。
- 推送后 15m / 1h / 6h / 24h 是否还有可执行观察窗口。
- 哪些规则需要调高或调低权重。

## 不直接做什么

学习层不应该直接输出：

- 买入或卖出建议。
- 自动下单行为。
- 黑箱式风险等级。
- 无证据的“必涨”“必跌”判断。

它应该输出：

```text
规则调整建议
证据
样本数量
置信度
可能副作用
是否需要人工确认
```

## 推荐目录

```text
src/chainmind/learning/
├── feedback/      # 用户反馈、点击、忽略、人工标注
├── evaluators/    # 规则命中率、误报、漏报、钱包信号评估
├── backtesting/   # 历史样本回测
└── advisors/      # 规则调整建议、策略总结
```

数据库侧可以使用：

```text
database/rules/
```

保存规则版本、规则建议和启用记录。

## 推荐闭环

```text
分析 token
→ 推送或入库
→ 记录后续表现
→ 每日复盘
→ 识别误报 / 漏报
→ 生成规则调整建议
→ 人工确认或高置信度自动启用
→ 形成新的规则版本
```

## 关键原则

- 实时判断要稳定、可解释。
- 学习结果要有样本和证据。
- 规则调整要版本化。
- Hermes 可以学习“哪里判断错了”，但不直接绕过评分系统。
- AI 可以总结复盘，但不能凭空修改规则。
