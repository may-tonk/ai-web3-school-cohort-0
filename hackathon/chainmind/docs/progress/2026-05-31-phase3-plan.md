# 2026-05-31 Phase 3 执行计划

## 1. 阶段三口径

当前项目文档中对 Phase 3 / 阶段 3 有三种表述：

- `docs/roadmap/07-mvp-roadmap.md`：Phase 3 是 Entity Cluster Score。
- `docs/roadmap/08-execution-plan.md`：阶段 3 是 Dune 深度分析。
- `docs/learning/13-token-analysis-data-analyst-workflow.md`：Phase 3 建议做安全 API 接入。

本阶段统一定义为：

```text
Phase 3 = Dune 深度分析产品化 + 安全 API 最小接入 + Entity Cluster v0.1
```

也就是说，本阶段不是重新推翻 Phase 2，而是把已经跑通的真实 Dune 分析链路整理成更稳定、可测试、可复盘的正式能力。

## 2. 阶段三目标

阶段三的目标是让 ChainMind 从：

```text
脚本可以跑真实 token
```

升级为：

```text
输入 token
-> 执行 Dune 深度查询
-> 读取或恢复缓存
-> 清洗并映射为 TokenSnapshot
-> 补充安全 / holder / 合约风险字段
-> 输出 Risk / Entity / Security / Data Quality 证据
-> 保存可复盘结果
```

## 3. 阶段三不做什么

本阶段暂不做：

- 不做自动交易。
- 不做价格预测。
- 不做复杂前端。
- 不做全市场高频扫描。
- 不做完整 AI 报告生成。
- 不强依赖 MySQL 落库。
- 暂不把真实样本库扩展到 10-20 个作为阶段验收标准。

真实样本扩展仍然重要，但暂时放到后续校准阶段，不作为当前第一个阶段三执行单元的必需交付。

## 4. 输入与输出

### 输入

```text
token_address
chain=bnb
Dune query ids
可选缓存目录
可选安全 API / RPC 配置
```

### 输出

```text
TokenSnapshot
AnalysisResult
Dune rows cache
execution_id recovery files
risk_evidence
entity_cluster_evidence
security_evidence
data_quality
可选 Markdown / JSON 输出
```

## 5. 模块边界

### scripts

`scripts/` 只保留薄入口，负责解析 CLI 参数和打印结果。

### orchestration

`src/chainmind/orchestration/` 负责单 token 深度分析编排：

```text
load config
run or load Dune query rows
map rows to TokenSnapshot
merge optional security data
run scoring
return structured result
```

### data

`src/chainmind/data/` 负责外部数据接入：

```text
Dune API client
query cache
security API client
RPC / explorer helper
```

### cleaning

`src/chainmind/cleaning/` 负责清洗外部数据：

```text
address normalization
number conversion
timestamp normalization
dirty row handling
confidence warnings
```

### scoring

`src/chainmind/scoring/` 负责评分和证据：

```text
token risk
entity cluster
opportunity
priority
data quality
```

## 6. 推荐执行顺序

### Step 1：抽出正式 Dune 分析编排模块

把 `scripts/analyze_dune_token.py` 中的核心流程迁移到：

```text
src/chainmind/orchestration/analyze_dune_token.py
```

脚本保持原有 CLI 行为不变。

### Step 2：标准化 Dune Query Set

固定当前核心查询：

```text
token_trading_activity
five_minute_flow
early_buyers
early_buyer_funding
```

holder 集中度短期优先考虑 API，不强制在本阶段补 Dune `holder_snapshot.sql`。

### Step 3：抽出 Query Cache

把 Dune rows cache 和 execution recovery 从脚本中抽到正式模块：

```text
src/chainmind/data/query_cache.py
```

### Step 4：完善 Dune 清洗层

新增或完善：

```text
src/chainmind/cleaning/dune_cleaners.py
```

重点处理空值、异常数值、地址大小写、时间字段和行级质量提示。

### Step 5：接入真实 API 并扩展 TokenSnapshot 字段

本阶段不再先做纯空字段容器，而是围绕真实 API 响应直接设计字段映射。

第一批接入目标：

```text
DexScreener：market / liquidity / pair / volume / price change
GoPlus Token Security：honeypot、税率、权限、LP、holder 风险等安全字段
BNB RPC：owner、proxy、只读合约状态补充
Honeypot.is：卖出模拟和 honeypot 交叉验证，可选
BscScan / Etherscan V2：源码、合约元数据、holder 信息，可选或需要付费计划
```

在保持旧样本兼容的前提下，补充：

```text
holders
contract
security
```

短期仍可用 dict，不急着拆复杂 dataclass。API 请求失败时不能中断分析，应记录 warning 并降低 data_quality。

### Step 6：实现 API Client 与字段映射

新增或完善：

```text
src/chainmind/data/dexscreener_client.py
src/chainmind/data/goplus_client.py
src/chainmind/data/honeypot_client.py
src/chainmind/data/bnb_rpc_client.py
src/chainmind/data/bscscan_client.py
src/chainmind/data/security_mappers.py
```

第一版优先落地字段：

```text
is_honeypot
buy_tax
sell_tax
owner
owner_renounced
is_proxy
holder_count
top_holder_ratio
high_risk
warnings
```

API 或 RPC 失败时，分析不应中断，只降低 data_quality。

### Step 7：实现 Entity Cluster Score v0.1

新增：

```text
src/chainmind/scoring/entity_cluster.py
tests/unit/test_entity_cluster_scoring.py
```

第一版只做低成本证据：

```text

```

## 7. 当前验收标准

阶段三当前最小验收标准：

- `scripts/analyze_dune_token.py` 仍能作为 CLI 使用。
- Dune 编排逻辑可以被测试直接调用。
- Dune rows cache 可以复用。
- Dune 返回缺字段或空 rows 时不会崩溃。
- `TokenSnapshot` 能承载安全和 holder / contract 补充字段。
- Entity Cluster Score v0.1 有独立输出。
- 安全字段缺失时会降低 data_quality，而不是伪造正常状态。
- `python -m pytest` 通过。

## 8. 需要确认的决策

目前建议采用以下取舍：

```text
holder 集中度：短期优先 API，不强制 Dune holder_snapshot
安全数据：优先 GoPlus / Honeypot / RPC 只读中的最小可用组合
存储方式：先 JSON / cache 文件，不急 MySQL
Entity Cluster：先独立输出，再决定是否影响总 grade
真实样本扩展：暂缓，不作为当前验收标准
```

如果以上取舍确认无误，下一步进入 Step 1：抽出正式 Dune 分析编排模块。
