# 2026-06-05 Phase 4 Plan

## Scope

This phase uses the execution-plan definition of Phase 4:

```text
Phase 4A = complete scoring package + Copyability v0
```

The goal is not to finish full Wallet Alpha yet. The current data sources can
support token-level copyability, but full wallet historical alpha still needs
more stable wallet-history inputs such as GMGN, Nansen, or Dune wallet profile
queries.

## Why This Split

Existing roadmap documents use different Phase 4 names:

- `docs/roadmap/07-mvp-roadmap.md`: Wallet Alpha + Copyability.
- `docs/roadmap/08-execution-plan.md`: complete scoring system.
- `docs/learning/13-token-analysis-data-analyst-workflow.md`: AI explanation layer.

For implementation, this phase follows the execution-plan path first. It adds
the missing scoring surface while keeping room for future wallet-level data.

## Copyability v0 Boundary

Copyability v0 answers:

```text
If a token has an apparent opportunity, is there still a reasonable observation
or follow window for a normal human user?
```

It uses token-level fields already present in `TokenSnapshot`:

```text
market
flow_5m
early_buyers
funding
security
```

It should not claim that a wallet is a proven alpha wallet. That requires
wallet history, realized PnL, win rate, hold duration, entry timing, and
post-entry price path data.

## Extensibility Rules

1. Keep `copyability.py` independent from API clients.
2. Keep the module input as `TokenSnapshot`.
3. Return the shared `ScoreResult` shape.
4. Use rule evidence with stable `rule_id` values.
5. Do not hard-code future data-source assumptions into scoring.
6. Add new wallet-level signals later by extending snapshot fields and adding
   new evidence rules, not by rewriting the scoring package.
